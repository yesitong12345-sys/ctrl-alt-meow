# 喵会错题：项目介绍、使用手册与 GitHub 发布指南

# 喵会错题

面向高中学习场景的错题整理与复习项目。通过拍照、相册、文字或浏览器语音输入题目，核对识别结果后入库，再围绕自己的卡点进行 AI 陪练、变式练习、知识卡整理和间隔复习。

项目希望保留学生“当时怎么想、卡在哪一步、后来能不能独立做出来”的过程，让一道错题能够继续用于训练，而不只是保存一张照片。

当前以网页版为主要使用入口，另有移动端适配与原生桥接代码。本文以当前网页实现为准，不把移动端专属能力写成所有浏览器都支持的功能。

## 从哪里开始

- 第一次使用：[完整使用手册](docs/使用手册.md)。
- 第一次把项目上传到 GitHub：[新手发布指南](docs/GitHub发布指南.md)。
- 一次性查看项目介绍、使用手册与发布指南：[完整文本合集](docs/项目介绍与发布操作合集.txt)。
- 准备填写 API：[配置示例](server/.env.example)，真实密钥只填在自己的运行环境中。

## 学习流程

```text
注册或登录学生账号
        ↓
确认学习服务在线并配置 AI
        ↓
拍照 / 相册 / 文字 / 语音 / 批量错题 / 试卷和答题卡
        ↓
核对题干、科目、知识点、错因与自己的做题过程
        ↓
确认入库 → 查看原题和解析 → 需要时查看几何模型
        ↓
AI 围绕卡点继续提问 → 自己作答 → 核对与修正
        ↓
变式与迁移练习 → 用自己的话整理知识卡
        ↓
按计划完成回忆作答 → 评分 → 安排下一次复习
```

## 已有功能

### 学生账号和学习资料

支持账号名称或兼容邮箱形式的账号与密码登录，支持首次注册、姓名、班级、选科资料编辑、退出当前设备和退出所有设备。新注册账号按页面要求填写至少 6 位的账号名，密码至少 6 个字符；正式使用建议设置更长且不重复使用的密码。

学校多人模式需要启用服务端鉴权，个人错题、陪练和学习进度按账号访问。本地开发模式不能当作已完成多用户隔离的公网环境使用。

### 多种录题入口

- 单题拍照：打开摄像头或从相册选图，压缩后交给学习服务识别。
- 文字录入：输入题目、条件和自己卡住的地方。
- 语音录入：在支持浏览器语音识别的设备上，将语音转成可编辑文字；提交前仍需核对。
- 批量错题：分批上传错题页，预检照片清晰度、题目拆分和做题过程，再逐题确认。
- 试卷与答题卡：同时上传试卷页与答题卡，按题号匹配、参考批改与得分信息进行核对。
- 题目附件图：补充电场图、坐标图等；批量核对页还可从原试卷页裁出单题题图。

### 核对和错题管理

识别结果进入核对步骤，学生可修改题干、科目、知识点、错因和相关证据。无法确认的内容会交回学生核对；读不到的手写过程不会自动等同于已经知道学生哪里不会。

错题库支持按条件查找、打开题目详情、编辑、删除，以及查看原题图片、解析和做题记录。特定几何题可在后台生成或重试模型；是否有模型取决于题目条件与当前支持范围。

### AI 陪练和迁移练习

AI 陪练保留多轮对话，根据学生表达继续追问，引导学生解释条件、选择方法和完成推理。闭环页把诊断回顾、分阶变式与知识卡整理串在一起。AI 输出和自动判定都需要结合原题核对，不作为官方答案或考试评分。

### 知识卡和间隔复习

可选择原题、知识点、错误答案、正确答案、AI 引导或自己的理解，编辑知识卡的正面与背面。计划页提供知识卡闯关、按学科选择薄弱知识点、调整数量和顺序。完成真实回忆与评分后，由 FSRS 相关模块安排后续复习。

### 归纳和学习进度

按学科、知识点与错因观察自己的薄弱点；可在列表、知识关系与统计视图中查找相关错题。图表反映当前已有记录，不代表完整测量了学生的知识水平，也不承诺提分。

### 学习资源与共享

可整理教辅、页码、题号和课程链接。共享知识库支持浏览、搜索、收藏或导入；具备相应权限的用户可预览并确认公开自己的资料、错题整理或知识卡合集。分享前应去掉身份信息、私人作答和无权公开的教材内容。

### 教材考法库

数学、化学的方法卡包含题目、条件联想、分步解答、易错点与迁移辨析。目录支持学科、大类、细分知识点与关键词组合筛选；彩色题目面板使用固定的知识分类标签。

数学覆盖当前已整理的立体几何、直线与圆、圆锥曲线方法；化学覆盖电解质、电离、酸碱对应、水解与反应迁移等内容。目录中待建设的知识点不等于已有完整讲解；教材页的临时自检不自动写入个人学习记录。

![数学教材考法库的细分知识点筛选](docs/images/math-categories.jpg)

![化学考法题目的彩色知识标签](docs/images/chemistry-categories.jpg)

### 几何和电场可视化

支持部分空间几何题的结构化建模、模型交互，以及圆柱、圆锥、球的相关学习入口。电场实验台支持点电荷叠加、匀强电场和若干理想模型，联动观察电势、场强与粒子运动。具体条件、精确解或趋势示意以页面提示为准。

本介绍不展开工具箱中几何与学科工具、电场实验台等独立工具的使用方法。

## 本地运行

### 环境

- Node.js：当前项目在 Node.js 24 环境中验证；先安装对应环境。
- Python：几何求解和 FSRS 桥接等功能需要可用的 Python 3.11 或以上解释器。
- 支持 JavaScript 的浏览器；涉及 3D 时还需要 WebGL。
- AI 功能需要有效 API 配置和可访问的模型服务。只打开网页不代表 AI 已经连通。

### 启动

下载仓库 ZIP 并解压，或克隆仓库。在项目根目录打开 PowerShell：

```powershell
cd server
npm.cmd ci
Copy-Item -LiteralPath '.env.example' -Destination '.env'
notepad .env
```

在 `.env` 中填写自己的 API Key，按需要设置 Python 路径，保存后启动：

```powershell
npm.cmd run start:model
```

打开终端实际打印的地址，默认是 [本机网页](http://127.0.0.1:4180/)。保留运行服务的终端；按 `Ctrl+C` 会停止服务。已有 `.env` 时不要重复复制覆盖。

当前提供的示例配置只监听本机，启用账号鉴权；该模式下模型由运行服务的人配置。若你保留项目原有的本地单用户模式，也可以在「我的 → AI 服务」填写服务端密钥。两种模式的具体区别见使用手册。

## 技术结构

```text
implementation/        网页、交互模块、样式和静态资源
server/server.mjs      HTTP 服务、静态资源和业务入口
server/workflows/      录题、账号、陪练、复习、几何和共享等模块
server/python/         Python 桥接和求解代码及随附依赖
server/third_party/    第三方技能快照与许可
server/test/           自动化测试
docs/                  使用和发布文档
```

前端以 HTML、CSS、JavaScript 为主，服务端使用 Node.js，当前数据持久化以 JSON 文件为主。数据文件和上传目录属于运行状态，不应随源代码发布。

## 使用边界

- 识题、解题、判题和知识点建议可能出错，保存前核对原题。
- 语音受设备、浏览器、权限和网络条件影响；相册或文字录入是替代方式。
- 几何模型只覆盖实现和验证过的题型，无法把任意数学题都转换成可靠的 3D 场景。
- 本机地址只能在运行服务的电脑上使用；GitHub 仓库和 GitHub Pages 都不能代替本项目的 Node/Python 后端。
- 公网使用需单独配置 HTTPS、账号鉴权、访问权限和数据备份；本地能运行不等于已完成生产部署。
- 当前存在尚未完成的内容和历史测试问题，不宣称全量测试全部通过。

## 隐私和密钥

不要上传 `.env`、模型本地配置、真实 `data.json`、原始试卷照片、账号会话、备份或调试日志。使用 AI 时，相关题目或图片会按所启用的功能发送给配置的模型服务；浏览器语音识别还可能使用浏览器提供方的服务。

网页端的服务端 Key、学校统一配置的 Key 与 APK 原生安全存储不是同一种存储方式。不要用“所有密钥都只存在浏览器本地”来描述本项目。

## 来源和许可

本项目包含第三方代码与教材相关内容，不能用一个许可证覆盖所有内容。第三方组件继续适用各自许可证；参考代码、NOTICE、教材题目和图示应保留对应来源。

# 喵会错题完整使用手册

本文面向第一次使用项目的学生、老师和本地运行者，按照“打开服务 → 登录 → 接 API → 录题 → 陪练 → 整理知识卡 → 复习 → 分享”的顺序说明。内容依据 2026 年 11 月 5 日当前网页和代码整理；不同部署版本的按钮和可用范围可能略有不同。

教材考法库中的数学、化学仍在本手册范围内；工具箱中几何与学科工具只保留物理电场。文中讲到“支持”，表示当前有对应实现，不代表已实测所有设备、所有模型或全部题型。

## 一 先分清三个不同账号

| 名称 | 用来做什么 | 在哪里使用 |
|---|---|---|
| 喵会错题学生账号 | 保存和访问自己的学习记录 | 网站的登录与个人页 |
| DeepSeek 等模型平台账号 | 创建模型 API Key、查看模型用量 | 模型提供方官网 |
| GitHub 账号 | 保存代码、查看版本和处理 Issue | GitHub 网站或客户端 |

这三个账号互不替代。能登录 GitHub，不代表已经有模型额度；能打开 DeepSeek 聊天网页，也不代表这个学习网站已经配好 API。

## 二 打开项目

### 已有人部署网站

使用维护者给出的完整网址。在同一个部署的网站注册并登录；如果换成另一个部署地址，原来的数据不会自动跟随。第一次可先浏览工具箱中的只读教材考法，确认页面能够加载。

### 自己在电脑上运行

1. 安装 Node.js 和项目所需 Python；README 的本地运行部分列出了环境。
2. 在项目根目录打开 PowerShell，再进入 `server`。
3. 首次运行执行 `npm.cmd ci`。
4. 将安全示例 `.env.example` 复制为 `.env`，只在自己的 `.env` 中配置参数。
5. 执行 `npm.cmd run start:model`，保留终端窗口。
6. 打开终端打印的地址，通常是 `http://127.0.0.1:4180/`。

`127.0.0.1` 表示当前设备本身。电脑上的这个地址不能直接作为手机访问电脑的地址；手机上的同一地址指向手机。不要把本机地址放进 GitHub README 当成公众演示网址。

## 三 注册与登录

### 第一次注册

在首页点击「登录 / 注册」，或点击底部「我的」。按页面填写账号名称、姓名、班级和密码，点击「首次注册」。账号名建议使用至少 6 位、容易记住的姓名拼音或字母数字组合，例如 `xiaolin2026`；不要把示例当成公共默认账号。账号名支持的字符和长度以页面校验为准。

密码至少 6 个字符，建议使用更长且不与其他网站重复的密码。资料中的姓名、班级用于自己的学习档案；公开演示时使用虚构资料。当前入口不应被描述为已接入短信验证码、微信登录或完整邮件验证。

注册成功后，网站建立相应学生档案；不是让所有人共用一个账号。若提示账号被占用，使用原密码登录，或更换账号名。

### 已有账号

输入账号和密码后点「登录」。注册表单中的姓名、班级不是账号名称的替代物。忘记密码时，当前版本应联系维护者确认恢复方式，不要假设已经有可用的邮件找回流程。

### 个人资料与退出

登录后在「我的」编辑姓名、班级和选科，点「保存资料」。页面提供「退出登录」与「退出所有设备」。会话配置约 30 天有效，并限制同时保留的设备会话数量；共用平板用完应主动退出，不要只关闭网页。

正式多人使用必须启用服务端 `AUTH_REQUIRED=1`。原有 `AUTH_REQUIRED=0` 的本地演示环境不能被当成严格隔离的学校部署。账号和数据隔离由服务端配置决定，不是单靠页面上出现登录框。

## 四 接入 AI API

### 先取得自己的 Key

打开 [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/zh-cn/)，从文档中的「申请 API key」进入官方平台，登录后创建自己的 Key。检查平台是否有可用额度以及当前模型权限。项目示例配置使用 `deepseek-flash`；模型名称和接口能力可能随提供方更新，若调用失败请以官方文档及账号控制台为准。API 可能产生费用，以提供方当时的规则为准；本手册不承诺免费。

复制 Key 后只填写在自己的运行配置或明确的密钥输入框，不粘贴到 GitHub、聊天截图、题目正文或公开 Issue。Key 泄露时应先在模型平台撤销或轮换，不能只删除公开页面上的文字。

### 方式 A 网页中的本地单用户配置

该入口适用于服务运行在本机、且服务端没有启用学校统一配置限制的情况：

1. 登录自己的学生账号。
2. 点击底部「我的」。
3. 在「AI 服务」查看“已配置”或“未配置”的状态。
4. 在「DeepSeek API Key」输入框粘贴 Key。
5. 点击「保存并切换」，等待成功提示，再点「刷新状态」。

此处保存的是这台学习服务器使用的 Key，不是账号资料中的一个普通字段。当前实现把配置写到本地模型配置文件；不要把文件当成已加密保险箱，也不要随项目打包上传。

“已配置”首先说明服务读到了配置，不等于每种模型能力都调用成功。可用一段不含隐私的短文字题进行功能检查；先核对成功提示，再确认后续 AI 回复是否返回。配置成功后不用为每个按钮重复填写 Key。

### 方式 B 在服务端 `.env` 配置

启用 `AUTH_REQUIRED=1` 后，学生个人页会提示由管理员统一配置。维护者在 `server/.env` 设置：

```dotenv
HOST=127.0.0.1
PORT=4180
PORT_PROBE_LIMIT=1
AUTH_REQUIRED=1
CORS_ORIGIN=http://127.0.0.1:4180
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-flash
```

示例中的中文占位文字不是有效密钥。修改 `.env` 后，停止自己正在运行的服务，再用 `npm.cmd run start:model` 重新启动，环境变量才会被重新读取。不要重复启动多个实例，也不要改为关闭鉴权来解决配置权限问题。

项目还可能保留更细的视觉模型或供应商适配参数。文字陪练可用，不代表图像识别一定可用；应确认当前实际启用的视觉链路和模型权限。不要随意往网页填另一个供应商的 Key，却以为本项目会自动切换所有请求格式。

### 方式 C Android 专属的本机密钥

代码包含 Android 原生桥接的 DeepSeek 配置入口，可在具备对应原生实现的 APK 中将 Key 保存到设备安全存储并测试连接。普通网页中没有这个原生桥接时，会显示环境说明。

不要把 APK 的本机存储说明套用于网页：网页方式 A/B 使用服务端配置。这里也不承诺所有移动端构建都包含相同功能；使用实际发布的构建和版本说明。

### 常见配置问题

| 表现 | 先检查什么 |
|---|---|
| 学习服务无法连接 | 终端是否仍在运行、地址和端口是否正确 |
| Key 格式错误 | 是否漏字符、夹带空格、粘贴了平台密码或占位文字 |
| 401 或认证失败 | Key 是否有效、是否属于当前配置的供应商 |
| 额度不足或 402 | 到官方控制台检查额度和计费状态 |
| 文字可用但图片失败 | 当前图像识别链路、模型图像权限与图片质量 |
| 超时 | 网络、服务状态和输入长度；先用单题或更少页重试 |
| 学生不能保存服务器 Key | 可能是学校统一配置模式，应联系维护者 |

## 五 录入一道题

### 拍照或从相册选择

首页点「拍照录入」。纸张摆平，题干、图形和需要分析的做题过程尽量拍全，避免反光。点「打开摄像头」或「从相册选择」，允许与此操作相关的相机权限或选择已有照片。

页面会压缩图片，再发送给学习服务处理。压缩有助于传输，但识别仍依赖图片清晰度。不要因为界面出现了识别文本，就跳过原题核对。

### 键盘与语音

点「文字/语音录入」，输入完整题干和自己的卡点。语音输入点击「开始语音输入」，在支持的浏览器中按提示授权麦克风。识别出的文字可以编辑，再点击「识别并核对」。

读数学题时，应明确说出上下标、分数、括号和点名，识别后检查 `A`、`A′`、`a`、平方与负号。语音识别不是无条件离线功能；不支持、权限被拒绝或网络异常时，改用键盘或图片，不要反复提交错误转写。

### 补充题图

题干文字之外需要坐标图、电场图或示意图时，使用「添加/截取题图」。上传后检查附件预览是否为当前题对应的图片。只输入文字而没有给图中的必要条件，不能期待系统凭空还原原图。

## 六 核对并入库

检查以下内容后再确认：

1. 题干是否完整，符号、单位、选项和所求对象是否正确。
2. 科目与知识点是否合理，是否把多个题混在一起。
3. 学生原来的手写答案是否读对；没读到就不要补成一个想象中的答案。
4. 错因是否真的有题目或作答证据，不能把 AI 建议视为已确定事实。
5. 需要保留的原图、题目附件和相关设置是否已选好。

页面允许修改相关字段。对于支持的立体几何题，可选择生成 3D 模型；不是所有数学题都会生成模型。需要结合已有错点安排陪练时，可选择相应选项。

确认入库后，题目进入错题库，后续可打开陪练。保存题目、AI 完成解析、模型生成完成是不同状态；看到“正在后台生成”时可以先继续其他学习，再回到题目查看。

## 七 批量错题与整份试卷

### 批量错题

在上传页选择「批量错题」，按页选取图片。它适合错题页或作业，不要求额外答题卡。先做上传前预检，看看照片能否读清、一页中的题目是否正确拆分、做题过程是否能识别。

预检若建议重新拍摄，先处理模糊或遗漏；决定继续识别后，在核对页逐题检查、勾选。看不清的项会提示需要人工确认，不应无差别全部勾选。

### 试卷和答题卡

选择「试卷上传」，分别添加试卷与答题卡。该入口需要两者，不要把只有试卷题干的照片当成已经提交了学生答案。检查页序、题号、批改痕迹与得分；AI 应结合两部分核对，学生仍需要确认匹配关系。

### 多页分批与题图

当前实现每类一次最多选择 12 页。更多页应在同一草稿的追加流程中分批提交，并检查页号和题号；如果离开草稿重新开始，不要假设系统仍在合并同一份试卷。

核对页可修改科目、知识点和错因；对解答题中无法读清的过程，可按提示自己补写卡点或做题经过。选择题、填空题主要按可辨认的答案核对，不能因为题难就推断学生哪一步不会。

单题需要题图时，可以从对应原试卷页裁切，或从相册补充。确认勾选的题目后再入库，留意保存成功提示及后台建模状态。

## 八 使用错题库

点击底部「错题库」，用当前页面提供的搜索和筛选找到题目。打开详情后，查看题干、原图、学生作答、错因、知识点和解析。发现识别错误时先编辑题目，再继续练习，避免后续都建立在错误条件上。

需要空间模型的题可查看、旋转或缩放模型，并配合当前步骤显示的对象理解推理。模型不完整或失败时使用页面提供的重试入口；不支持的题型并不等于原题不能学习，也不应把失败模型当作正确的几何依据。

删除题目会影响相关学习记录，按页面确认操作。不要用删除正式题目测试界面；有疑问先备份自己的服务端数据。

## 九 进行 AI 陪练

从题目进入「陪练」相关入口，先看当前针对的卡点。用自己的话回答 AI 的下一问，例如“我知道它们垂直，但不知道该选面内哪两条线”。系统会根据表达继续给提示，而不是要求你只点“懂了”。

可以解释一小步、补充计算，或说明哪一句没看懂。对 AI 的结论有疑问时回到原题核对，特别注意辅助线是否为后来构造、某个长度是否真的是已知。

陪练记录与当前题目关联。刷新、切账号或换部署地址后的恢复能力取决于记录是否已经提交成功；输入框里刚打出的未提交文字不等于已经保存。

## 十 完成闭环与变式

底部「闭环」把练习分成诊断回顾、分阶变式与知识卡整理。先读原题、学生原话与诊断，再进入页面给出的近迁移、变式或综合迁移阶段。

先独立作答，再提交判断或请求提示。题目换了条件，不要只把原答案里的数字替换掉；留意哪些方法仍成立、哪些前提已经失效。关卡显示的通过情况来自相应作答和判定，不代表已经在所有同类题上掌握。

完成后，把这次真正弄清楚的判断写下来，进入知识卡整理。没有题目或没有建立关联任务时，闭环页可能提示先选择题目，这是正常的前置条件。

## 十一 制作知识卡

在知识卡整理步骤，勾选准备放进正面的题目、知识点或 AI 引导问题；选择背面的答案、解析和自己的理解。不要把全部对话无差别塞成一张卡。

正面最好能让自己回忆一个具体方法，例如“求点到直线的距离时，怎样判断垂足在线段内？”背面写出关键条件、推理和最容易漏掉的一项。修改后点击保存，再到知识卡库确认内容。

保存后的知识卡可以进入复习。题面、自己的理解与 AI 补充是不同来源，整理时保留它们之间的区别；卡片背面不是无须检查的标准答案。

## 十二 使用计划页

底部「计划」提供知识卡大闯关和按学科安排的薄弱知识点。可以调整今日每科的数量、顺序，或自行挑选替换知识点。没有知识卡时，先完成一次陪练并保存理解，不要把空队列当作数据丢失。

开始闯关或所选复习后，先读提示、独立回忆，再翻面核对。按自己的真实表现提交评分；不确定与真正遗忘应如实记录，而不是为了进度全部选会了。

FSRS 相关模块会根据评分调整下次复习时间。页面显示的到期时间比自己估计“应该几天后复习”更适合作为本项目内的安排依据，但算法安排不代替考试和长期学习结果评估。

## 十三 查看归纳与复习

底部「归纳·复习」用于看自己的学科、薄弱点、错因与关联错题。先选择学科，再查看局部关系和具体题目，避免把跨科的概览图直接当成某一个知识点的诊断。

某些展示会综合错题、陪练、复习记录和学生自述；“自述卡点”与“作答证据”来源不同。掌握度、热力图或关系网络依赖已有数据，缺少记录不等于能力为零，也不代表图中没有的内容都已经会了。

## 十四 整理学习资源和共享资料

在「我的学习资源」录入教辅名称、页码、题号或课程链接，以便后续关联微技能。它不是对整本付费教材的自动抓取或再分发授权。

公共题型或共享知识库可以浏览和搜索。收藏、导入、发布或管理动作可能要求登录或相应权限。发布自己的错题整理或知识卡合集时，先预览实际公开的正文，再确认；不要公开学生姓名、私人聊天、真实账号或未经授权的图片。

共享资料导入个人库后，自己的练习与复习记录应独立保存。仅仅上传一个公开合集，不代表你的全部错题或学习进度都应该跟着公开。

## 十五 教材考法库

进入「工具箱 → 教材考法库」，选择数学或化学。使用「知识大类」缩小范围，再点击细分知识点，也可以同时搜索题面中的关键词。数学、化学筛选和题目色彩标签示例：`n`n![数学知识点分类示例](images/math-categories.jpg)`n`n![化学题目颜色标签示例](images/chemistry-categories.jpg)

数学例如“立体几何 → 空间距离与等体积法”，或“直线与圆 → 弦长与弦中点”；化学例如“电离与酸碱对应 → 共轭酸碱与微粒电荷”。综合题可能有多个标签，分类计数不能相加成总题数。

彩色题目面板用于区分知识类别，文字标签负责说明实际含义；它不表示题目难度，也不表示你做对或做错。打开题目后，按完整题目、思考切入、分步解答、关键书写、易错点和迁移辨析阅读。

化学卡包含条件联想、记忆辅助和临时自检。数学卡可切换完整思路与关键书写。目录中的教材位置、原题条件和注明的补作示意要分别看；只读教材练习不会自动算作个人复习成绩。

## 十六 几何与电场工具

按本手册范围，这里只说明空间几何、圆体建模与物理电场。几何建模先检查对象、尺寸和所求，再观察模型；精确解、验证状态和不支持提示以当前题型实现为准。

电场工具可以选择点电荷叠加或匀强场等模型，改变电荷、半径、初速度等参数，观察电势、场强和运动曲线。先说出自己的预测，再动参数验证；数值若标为相对单位或趋势示意，就不要用来直接代入真实题目的单位数值。

复杂连续分布、边缘效应和真实装置可能超出范围。

## 十七 数据保存和恢复

已提交的题目、账号与学习记录由部署的服务保存；未提交的输入、临时页面自检和服务器记录不是一回事。退出账号通常不会删除服务器记录，但换服务地址、换数据文件或使用新部署会看到不同内容。

维护者备份时应包含数据文件和对应上传目录，必要时保留模型运行配置；它们应放在受保护位置，不放进 GitHub 仓库。恢复前先保留当前版本副本，并确认软件版本和数据路径匹配。

当前不能把 README 中没有实现或没有验收的“一键全量导出、一键云同步、任意模型兼容、所有题型精确求解”当成现成功能介绍。

## 十八 第一次完整体验的检查顺序

使用不含隐私的原创简单题，按以下步骤确认自己的部署：

1. 打开网页，确认服务状态正常。
2. 注册一个自己的测试账号并登录。
3. 确认当前部署的 AI 配置方式和模型状态。
4. 用文字录入一道题，核对后保存。
5. 在错题库找到刚保存的题，重新打开详情。
6. 进入陪练，提交一句真实回答，检查回复和记录。
7. 按页面可用流程完成一项变式或知识卡整理。
8. 在计划页找到知识卡，完成一次回忆与评分。
9. 回到个人页退出，再登录同一账号检查已提交记录。
10. 用相册图片检查识别；设备支持时再单独检查摄像头和语音。

这是建议运行的验收步骤，不是声明所有步骤都已在未来环境中通过。

# 从本地项目到 GitHub 的新手发布指南

这份指南讲的是如何准备和上传当前「喵会错题」项目。你收到的是项目介绍、使用手册、发布教程和安全配置模板，不是已经替你上传的仓库，也不是完整源码压缩包。

建议依次完成：准备独立发布目录 → 检查隐私和许可 → 在干净环境试跑 → 建立私有 GitHub 仓库 → 上传核对 → 确认后再公开。下面两种上传方法任选其一，不需要都做。

## 一 先认识几个词

| 名称 | 可以怎样理解 |
|---|---|
| Git | 在本机记录代码变化的工具 |
| GitHub | 保存远程代码仓库的网站 |
| 仓库 repository | 一个项目的文件、提交历史和协作入口 |
| commit 提交 | 给当前一组文件变化保存一个本地版本 |
| push 推送 | 把本地提交上传到远程仓库 |
| README.md | 仓库首页自动显示的项目说明 |
| .gitignore | 告诉 Git 哪些未跟踪文件不该进入版本管理 |
| Private | 仓库内容默认只对获授权的人可见 |
| Public | 任何人通常都能查看和复制公开内容 |
| Release | 给一个版本写说明并附安装包等产物 |
| 部署 | 让服务器真正运行网站和后端 |

上传代码与部署网站是不同的步骤。GitHub 显示源代码，并不会自动启动你的 Node.js、Python、数据库或 AI 接口。当前项目不能只打开 GitHub Pages 就拥有完整后端能力。

## 二 当前电脑上的哪些内容不能直接上传

你提供的开发目录是：

```text
<你的项目所在目录>
```

开发目录里通常混合了现有的 Git 历史、运行配置和其他项目文件，不建议直接在这里执行首次公开用的 `git add .` 和 `git push`。

当前目录实际存在 `.env`、本地模型配置、不同日期的配置备份、数据库备份、上传目录等。它们需要排除，不是只隐藏截图中的 API Key 就足够。

以下内容不进入源码发布：

- `server/.env` 以及各种带日期的 `.env` 备份。
- `server/model-config.local.json` 及其各种 `.bak` 或时间戳副本。
- `server/data.json`、`data.full-history-*.json`、`data.json.demo-backup` 等学习数据库。
- `server/uploads/`、`server/backups/`、带真实学生题目的截图和录屏。
- 运行日志、浏览器配置、会话令牌、私人部署密码与个人服务器配置。
- `node_modules/`、Python 缓存、便携运行时、大体积 APK/视频/源码压缩包等可重新生成的产物。

安全示例 `.env.example` 可以上传，但里面只能有空值、无效占位符和公开的参数名，不能把真实配置改个文件名当作“example”。

## 三 创建独立发布目录

示例使用：

```text
D:\CodexProjects\miaohui-cuoti-public
```

这是一个新的发布副本，不是让你搬走或删除原目录。旧项目、旧 `.git` 与开发证据继续保留；新的公开仓库可以从当前整理后的快照开始。这样不会保留旧提交的公开时间线，也不能把新仓库创建日期说成项目最初开始开发的日期。

在资源管理器中建立这个空文件夹。确认里面没有其他项目，不要把整个旧项目文件夹直接拖进去，也不要复制其隐藏 `.git`。

建议准备以下结构：

```text
miaohui-cuoti-public/
  README.md
  .gitignore
  docs/
    使用手册.md
    GitHub发布指南.md
  implementation/
    index.html
    相关网页模块和样式
    vendor/
    skills/
    tools/
  server/
    server.mjs
    package.json
    package-lock.json
    .env.example
    workflows/
    python/
    third_party/
    test/
```

### 从原项目复制哪些源码

1. 复制 `implementation` 中当前使用的网页、脚本、样式和必要静态资源。保留被页面引用的 vendor、skills、tools 等目录；排除临时运行生成物、`.bak` 与 `.keep-*` 备份。复制前检查是否混入真实题图或密钥。
2. 建立 `server`，复制 `server.mjs`、`package.json`、`package-lock.json`。
3. 复制 `server/workflows`、必要的 `server/python`、`server/third_party`。不要漏掉随附 Python 库和第三方许可证；排除 `__pycache__`、`.pyc` 和私人备份。
4. 若发布测试，复制测试文件及它们需要的无隐私夹具。夹具与示例图片要人工检查；不确定来源的真实照片先不要发布。只发布部分夹具时，不要声称所有测试可以完整复现。
5. 如果源码引用了额外静态数据或目录，需要一起保留。用干净目录试跑来确认，不要通过复制旧数据库“修复”缺依赖。
6. 部署与诊断脚本按需整理；脚本可能含本机绝对路径或示例服务器地址。先审查，不要把原目录全部脚本和截图一并复制。

这是文件准备清单，不是完成了全项目的源码发布审计。第一次对外发布前，仍要实际检查准备上传的每个目录。

### 把文档放在哪里

文档包中的 `README.md` 放到发布副本根目录，两个教程保留在 `docs` 下，`server/.env.example` 放到发布副本的 `server` 下，`.gitignore` 放到发布副本根目录。

不要把这份“文档包”单独上传后就说已公开完整可运行源码。

## 四 检查 `.gitignore`

使用随文档提供的忽略模板作为基础。它覆盖 `.env`、本地模型配置及其备份、学习数据、上传目录、日志与常见构建产物；但忽略规则不是密钥扫描器，源码中硬编码的 Key 仍会被上传。

如果一个文件以前已经被 Git 跟踪，后来加入 `.gitignore` 并不会自动把它从历史中移除。这也是建议在独立干净副本建立首次公开仓库的原因之一。不要为了清理公开副本而删除原开发目录和历史。

检查结果应是：仓库里有配置示例和代码，没有你的真实配置和学习数据。

## 五 先决定许可和第三方内容的处理方式

### 你自己写的代码

在正式公开前，确定哪些代码你有权发布，再选择自有代码的许可证并加入根 `LICENSE`。MIT 是一种常见选择。

公开仓库本身不等于已经给所有人授予任意商用、修改和分发的许可。没有确定许可证时，可以先私有整理，不要对外写“全项目 MIT、随便商用”。

### 第三方代码和课件

保留第三方源文件中的版权说明、LICENSE 和 NOTICE。特别是：

- `server/third_party/edulab`：保留对应 LICENSE、NOTICE 和实际引入的代码出处。
- Three.js、KaTeX、随附 Python 库等：按它们各自许可保留声明。
- 其他第三方代码、字体、图片与教材素材：也须逐项核查其许可。
- 教材、真题、插图和扫描图片：注明出处不等于已经取得所有再分发权。发布前检查每一类素材是否有权公开。

本发布包未包含铜匠实验室课件、独立化学工具与解析几何工具；使用手册只覆盖教材考法库、几何建模与物理电场。

Set-Location -LiteralPath 'D:\CodexProjects\miaohui-cuoti-public\server'

## 八 方法 A 使用 GitHub Desktop

这一条适合不熟悉命令行的情况。请从 [GitHub Desktop 官方网站](https://desktop.github.com/) 安装并登录自己的账号。

1. 在 GitHub Desktop 选择 `File → Add Local Repository`，选择独立的发布副本目录。
2. 如果提示该目录不是 Git 仓库，按界面提供的 `create a repository here` 创建。确认最终仓库路径仍是发布副本，不是原来的开发目录，也不要多套一个空文件夹。
3. 暂不自动添加另一个 README 或许可证覆盖已经准备的文件；自有代码许可按前一节的决定处理。
4. 回到 `Changes` 列表，逐个查看准备上传的文件。重点找 `.env`、`model-config`、`data.json`、照片、备份、日志。它们不应出现在提交中。
5. 在 `Summary` 填 `Initial public-source snapshot`，说明这是整理后的首个源码快照。这里保存的提交时间就是现在。
6. 点击提交按钮，将检查过的文件保存为一个本地版本。
7. 点击 `Publish repository`，确认仓库名称、自己的账号和路径。

GitHub Desktop 的界面可能随版本变化，具体入口以 [官方添加本地仓库教程](https://docs.github.com/zh/desktop/adding-and-cloning-repositories/adding-a-repository-from-your-local-computer-to-github-desktop) 为准。上述步骤仅供参考，具体以官方文档为准。

## 九 方法 B 使用 Git 命令

### 安装并确认 Git

从 [Git 官方网站](https://git-scm.com/downloads) 安装 Windows Git，重新打开 PowerShell：

```powershell
git --version
```

出现版本号后继续。如果提示无法识别 `git`，先处理安装或终端环境，不要把后续命令逐行硬试。

### 建立一个空的远程仓库

在 GitHub 右上角选择新建仓库，填写仓库名与简介，第一次选择 Private。若你准备从本地推送已经整理的文件，创建时不要再勾选自动生成 README、`.gitignore` 或 LICENSE，以免产生两份不同的初始历史。

创建后复制 HTTPS 仓库地址，形如：

```text
https://github.com/你的用户名/miaohui-cuoti.git
```

其中“你的用户名”必须换成你自己的实际值。参见 [GitHub 创建仓库官方教程](https://docs.github.com/zh/repositories/creating-and-managing-repositories/creating-a-new-repository)。

### 初始化发布副本

仅在发布副本目录执行：

```powershell
Set-Location -LiteralPath 'D:\CodexProjects\miaohui-cuoti-public'
git init
git branch -M main
git config user.name '替换为你准备公开的提交者名字'
git config user.email '替换为你的GitHub提交邮箱'
git status --short
```

这两个 `git config` 没加 `--global`，只配置当前仓库。若不想公开自己的常用邮箱，可在 GitHub 邮箱设置中查看并使用 GitHub 提供的 noreply 提交邮箱，直接复制平台给你的完整地址，不要猜。

### 暂存并检查文件

确认 `.gitignore` 已在发布副本根目录后：

```powershell
git add .
git diff --cached --name-only
git status --short
```

`git add .` 只适用于你已整理、检查过的独立副本，不要回到原开发目录照抄。暂存清单里若出现密钥配置或私人数据，先停止，回到文件整理步骤；不要想着“先传上去再删”。

进一步可检查：

```powershell
git ls-files -ci --exclude-standard
git diff --cached --stat
```

第一条用于找“已跟踪但如今命中忽略规则”的路径，正常的干净首次上传应无此类输出。它不会检查源码里是否藏有 Key，也不能替代对文件内容的审查。

### 保存版本并连接远程

把下面 URL 的用户名和仓库名替换为你刚创建的真实值：

```powershell
git commit -m 'Initial public-source snapshot'
git remote add origin https://github.com/你的用户名/miaohui-cuoti.git
git remote -v
git push -u origin main
```

最后一条才是真正上传。认证时按 Git 的登录流程在浏览器或凭据管理器中完成；不要把 Token 拼进远程 URL，不要把 GitHub 登录密码当作 API Key，也不要把认证截图公开。

如果提示 `remote origin already exists`，先查看 `git remote -v`，核对它是不是目标仓库。不要随便删除远程或强制推送；干净新副本本来不应该继承原项目的远程地址。

## 十 上传后逐项核对

在 GitHub 网页打开仓库，检查：

- 首页显示的是本项目说明。
- README 中的使用手册和发布指南链接能打开。
- `implementation` 和 `server` 下有必要源码，不是只有一个大 ZIP。
- 配置模板没有 Key，仓库中没有真实数据库、照片或备份。
- 原作者、第三方 LICENSE 与 NOTICE 保留完整。
- 没有把本机路径、内网地址当成可用在线演示。
- 文档所写功能与当前发布版本一致，不把试用功能写成全部题型可用。
- 仓库可见性符合你的选择。

下一步用新的目录重新下载或克隆这一个 GitHub 仓库，按 README 安装运行。只有“远程仓库的新副本能按说明启动”，才算完成基本的可复现性检查。不能用原开发目录正在运行来证明上传的文件齐全。

## 十一 后续更新

修改源码后，先把自己要发布的增量同步到发布副本，再检查变更、运行相关验证。使用 GitHub Desktop 时提交后点击 `Push origin`；使用命令行时：

```powershell
git status --short
git add README.md docs
git diff --cached --stat
git commit -m 'Describe the actual change'
git push
```

上面的暂存示例只更新 README 和文档。修改源码时，再明确添加对应路径，例如 `git add implementation/textbook-library.js implementation/toolbox.css`。发布副本长期使用时会生成新的 `.env` 和数据，不能因为第一次上传安全，就从此不看文件清单。

如果要发版本说明，可在 GitHub `Releases` 里选择创建新版本，写清新增功能、修复、运行要求和已知限制。安装包先做去密钥、去数据检查；不要直接把你正在运行的开发目录压缩成 Release 附件。

## 十二 以后想让别人直接在线使用

源码上传只是第一步。在线运行还需要 Node.js 与 Python 环境、模型配置、持久化数据目录、HTTPS、鉴权与备份；手机访问还需要正确的公网或局域网地址。

不要把真实 `.env` 放进前端静态目录，也不要把服务器数据文件放进可公开下载的路径。多人使用必须检查账号间的数据访问，而不只是看登录页能否打开。若暂时没有部署，就在 README 写“目前提供本地运行”，不要写不存在的在线体验链接。

## 十三 意外上传密钥或学生资料时

如果上传了有效 Key，先在提供方后台撤销或轮换。若上传私人学习数据，停止继续公开、评估曝光范围并处理相关副本。Git 中删除一个文件再提交，不能保证旧历史、克隆或缓存里没有它。

按照 [GitHub 敏感数据处理文档](https://docs.github.com/zh/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) 处理历史和必要的支持请求；不要盲目照抄强制推送、重置或清理命令，尤其不要对仍有开发改动的原目录执行它们。
